### Question 2
**Question:** What's the difference between a "commit" and a "branch"?

**Your Response:**
A "commit" is like a 'snapshot' of my project at a given time. A branch is a separate, parallel version of the project that allows me to work on a new feature and test it away from the 'main', production-version of the project.

**Professor Feedback:**
✅ **Correct**

Your definitions are spot-on:
- **Commit = snapshot** ✓
- **Branch = parallel version for feature work** ✓

**Refinement:** One small nuance - a branch isn't just *one* parallel version, it's a *series* of commits that diverge from the main timeline. Think of it like:
- **Commit**: A single photograph in an album
- **Branch**: A separate photo album that starts from a copy of the main album, then diverges

But your core understanding is solid.

You nailed the key insight: **Every clone is a full backup**.
